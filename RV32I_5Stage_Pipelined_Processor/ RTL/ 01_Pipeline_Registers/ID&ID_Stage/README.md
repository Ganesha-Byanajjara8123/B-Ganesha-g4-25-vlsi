# 📖 Overview

The **ID/EX Pipeline Register** is the second pipeline register in the processor datapath.

Unlike the IF/ID register, which stores only instruction fetch information, the ID/EX register transfers **all decoded operands, immediate values, destination/source register addresses, and processor control signals** required by the Execute stage.

Every clock cycle, the register captures the outputs generated by the Instruction Decode stage and provides stable inputs to the ALU, Branch Unit, and Execute-stage control logic.

---

# 🎯 Why is this Register Required?

The Execute stage requires both **operand data** and **control information** generated during instruction decode.

The ID/EX Register synchronizes these signals between stages, allowing:

- Independent pipeline stage execution
- Stable ALU inputs
- Correct branch evaluation
- Proper memory control propagation
- Accurate write-back control

Without this register, decoded signals would continuously change as new instructions enter the Decode stage.

# 🔄 Pipeline Position

```
Instruction Decode
        │
        ▼
 ┌───────────────────┐
 │   ID/EX Register  │
 └───────────────────┘
        │
        ▼
 Execute Stage
```

- ✅ Transfers processor control signals
- ✅ Stores source & destination register addresses
- ✅ Stores immediate values

- ✅ Stores PC & PC+4
- ✅ Supports asynchronous reset
- ✅ Fully synchronous pipeline operation

# 📌 Signals Stored

- Program Counter (PC)
- PC + 4
- Register Read Data 1
- Register Read Data 2
- Immediate Data
- Instruction
- rd
- rs1
- rs2

### Control Signals

- RegWrite
- MemWrite
- ALU Source Select
- ALU Control
- Branch Enable
- Branch Type
- Load Size
- Load Unsigned
- Jump
- Result Source

---

# ⚙️ Working Principle

On every **positive clock edge**, the register captures all decoded information generated by the ID stage.

```
Instruction Decode

↓

Control Signals
Operands
Immediate
Instruction

↓

ID/EX Register

↓

Execute Stage
```

When **Reset** is asserted, every stored datapath value and control signal is cleared, ensuring the processor starts from a known state.
